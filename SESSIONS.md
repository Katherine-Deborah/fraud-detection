# Claude Code Session Plan — Fraud Detection Pipeline

This file is the source of truth for multi-session work on this project. Read `PROJECT.md` first for the full requirements — this file only sequences the work.

## How to use this file

- Work through sessions in order. Each session assumes the previous ones are done.
- At the **start** of a session: read this file, find the first unchecked session, read its "Prerequisites" and confirm they're actually true (don't assume — check the repo state).
- At the **end** of every session, without exception:
  1. Check off completed tasks below (`- [x]`).
  2. Add a dated one-paragraph note under that session's "Session log" listing what was actually done, what's left, and any deviations from the plan.
  3. Commit the work with a clear message (not "wip").
  4. If AWS resources were touched this session: run `aws sagemaker list-endpoints` and `aws sagemaker list-notebook-instances` and confirm nothing billable is left running. Note the result in the session log.
  5. If a session can't be finished in one pass, stop at a clean boundary (a working, committed state) rather than leaving something half-edited — the next session should never start by fixing broken code from an interrupted one.
- Do not skip ahead to a later session's tasks even if it seems faster — later sessions assume earlier infrastructure exists and is tested, not just written.

**Nuance to watch for:** make sure the train/validation/test split respects time order (no future transactions leaking into training) — this is a common and easy-to-miss fraud-detection-specific bug.

**Cost/safety check:** None — all local.

**Session log:**
- 2026-07-29: Added a SQLite-backed MLflow tracking server (`ghcr.io/mlflow/mlflow:v2.12.2`) to `docker-compose.yml` on port 5000, with a single named volume for both the backend DB and artifact store — decided over reusing Airflow's Postgres (see this session's user Q&A) to keep MLflow's lifecycle independent, matching the project's "add only what each session needs" pattern. Class imbalance handling was also decided up front with the user: **class weighting for every model, not SMOTE** (`class_weight="balanced"` for LogReg, `"balanced_subsample"` for RF, `pos_weight` in `BCEWithLogitsLoss` for the LSTM, and unsupervised contamination-from-train-fraud-rate for Isolation Forest, which sees no labels at all) — avoids synthetic points leaking across the chronological split and sidesteps the ambiguity of what SMOTE would even mean for a sequence input. Built `training/data_prep.py` as shared infrastructure for all 4 scripts: a **chronological** 70/15/15 train/val/test split by timestamp span (not row count, and not shuffled — the exact leakage bug the plan's "Nuance to watch for" flagged), a 29-column feature matrix (the 15 engineered features from `docs/dataset.md` + raw `amount` + a derived `is_first_txn` flag + 12 one-hot `merchant_category` columns), sentinel handling (the `-1` "no prior transaction" values in `time_since_last_txn_sec`/`geo_distance_from_last_txn_km` are replaced with the **train-split median** of their real values, never val/test), and a shared threshold-selection helper (`select_threshold_for_fpr`) that picks the operating threshold on **validation** at PROJECT.md's target FPR≤2%, then applies it unchanged to **test** for the final precision/recall/F1 — AUC-PR is computed directly on test since it's threshold-independent. Wrote and ran all 4 training scripts against the full committed dataset (3,507,193 train / 751,904 val / 750,903 test rows, fraud rate ~0.2% in every split): `train_logreg.py` initially failed to converge and scored a near-useless AUC-PR of 0.041 before adding a `StandardScaler` (raw feature scales span orders of magnitude, e.g. `time_since_last_txn_sec` in the hundreds of thousands vs. 0/1 flags) — after fixing that, it trained in 6.8s with AUC-PR 0.312, recall 78.6% @ threshold. `train_random_forest.py` (200 trees, max_depth=20, min_samples_leaf=20, class_weight=balanced_subsample) took 614.6s (~10.2 min) on the full training set and produced the best AUC-PR of the 4 models (0.655, recall 86.3%). `train_isolation_forest.py` trained in 27.5s (unsupervised, contamination=0.00198 from the train fraud rate) and, as expected for a model that never sees labels, was clearly the weakest (AUC-PR 0.050, recall 52.0%) — included as the required unsupervised baseline, not a competitive candidate. `train_lstm.py` builds per-account sliding-window sequences (left-padded, `seq_len=20`) via an `AccountSequenceDataset` that slices windows from a pre-sorted (account_id, timestamp) feature array on the fly rather than materializing all ~5M windows (which would be tens of GB) — trained on a deliberate, documented subsample of 10,000 of 50,000 accounts (~1M rows) for local-GPU (GTX 1650 Ti, 4GB) iteration speed, since sequence models cost far more per epoch than the tabular models at equal row count; 3 epochs on GPU (CUDA 12.1) finished in 35.7s and reached AUC-PR 0.641 with the **highest recall of all 4 models** (88.1% @ FPR≤2%), essentially matching Random Forest despite the much smaller training set. `training/compare_models.py` pulls each model's latest MLflow run, writes `docs/eda/model_comparison.png` (AUC-PR bar chart + grouped precision/recall bars) and `docs/model_comparison.md` (full results table, per-model imbalance rationale, and a written recommendation: **Random Forest** as the production candidate on AUC-PR, with LSTM flagged as the higher-recall alternative and a note that its result would likely improve further at full 5M-row scale via SageMaker in Session 6). One bug hit and fixed along the way: the first version of `compare_models.py`'s "what I'd try with more time" section had a template bug that interpolated `train_seconds` where account-count text was intended — caught on review of the generated doc, fixed, and the doc regenerated correctly. Verified end-to-end: `mlflow.search_runs` against `http://localhost:5000` shows all 4 models with `status=FINISHED` and real (non-placeholder) metrics, matching `docs/model_comparison.md`. No deviations from the planned task list beyond the two documented scale/scope decisions above (MLflow backend choice and LSTM subsampling), both flagged to and confirmed by the user before implementation per this project's architectural-decision-review convention.
